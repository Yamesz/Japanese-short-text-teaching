# 日語教學網站工作流程

建立或維護以「さくら先生」為教學角色、面向繁體中文學習者的日語教學網站。

## 先選擇內容模式

- **一般級數短文**：新增 N5、N4、N3 等單篇閱讀教材時，沿用同級數相鄰單元的頁面、資料與共用模組。
- **階梯故事**：同一故事提供不同級數版本，或以章節推進難度時，沿用 Progressive 既有切換方式；只有設計選擇會改變故事結構時才詢問使用者。
- **影片或逐字稿系列**：來源素材切成多篇、每篇有時間碼或字幕範圍時，使用 japanese-source-series-generator。
- **網站共用功能**：首頁篩選、學習進度、TTS、卡拉 OK、測驗或共用樣式，先檢查現有模組，再集中修改共用實作。

專案的實際目錄、共用模組與相對路徑見 [site-architecture.md](references/site-architecture.md)。新增一般單元時可使用 resources/template-lesson.html 作為起始版型，並依最近的同類頁面調整。

## 需求範圍守門（必須）

- 新增頁面、區塊、導覽列、按鈕或互動前，先確認它有明確來源：使用者要求、這份 Skill 的必備規範，或指定的既有教材範本。沒有來源就不加入。
- 不因為「方便導覽」、「提升體驗」或「看起來更完整」自行增加功能。覺得某項額外功能有價值時，可在交付說明中提出建議，先不實作。
- 交付前檢查本次新增的介面元素，確認每一項都能對應到上述來源；移除無法對應的項目。

## 多篇來源：逐篇獨立製作（必要條件）

當使用者提供多個文章來源或要求處理整個資料夾時，必須採用單篇文章的完整製作方式，依序一篇一篇完成。

- 每次只處理一篇來源：閱讀原文 → 規劃該篇教學重點 → 編寫本文與完整教學內容 → 製作單篇頁面 → 校對內容、檢查版面與互動 → 完成後才開始下一篇。
- 不得使用程式迴圈、批次產生器，或先彙整所有文章資料再一次輸出全部教學文章；即使程式內部依序寫檔，也不符合逐篇製作的要求。不得平行製作多篇來取代這個順序。
- 每篇依原文個別設計詞彙、動詞、助詞、文法、例句與測驗；不可只替換共用模板的資料就視為完成教學設計。
- 可沿用既有頁面版型、共用 CSS／JS 與檢查工具；這些工具限於支援單篇實作、網站功能與驗收，不得用來一次產生整批文章內容或頁面。
- 完成一篇後自行接續下一篇，不需要每篇都等待使用者確認；保留逐篇完成與驗收的紀錄。

## 一般短文必備教學單元

每篇 N5、N4、N3 一般短文都必須依以下順序呈現五個教學單元，不可省略或調換：

1. **精選單字**：整理理解本文所需的核心詞彙，附讀音與繁中釋義。
2. **動詞教室**：講解本文的重要動詞與用法，採個別動詞卡呈現，參考 `N5/文章1/index.html` 的「動詞寶庫」：
   - 每個重點動詞各用一張卡；動詞類別是卡片資訊，不可只把動詞分成第一、第二、第三類三大組，也不可漏掉中文釋義。
   - 卡片標示讀音、ます形與辭書形（適用時保留漢字），並標明第一／第二／第三類及繁體中文意思。
   - 每張卡提供活用表，至少列出辭書形、ます形、過去式、て形、ない形；可沿用網站既有的展開表互動。
   - 每張卡至少附一個自然且切合本文的日文例句和繁體中文翻譯；頁面支援 TTS 時，沿用既有朗讀按鈕。
   - 精選值得學習的本文動詞即可，不必收錄每個出現的動詞，也不固定卡片或例句數量。沿用共用互動時，確認展開按鈕和表格 ID 唯一且互相對應。
3. **助詞教室**：解析本文出現且值得學習的助詞，說明其在原句中的功能。
4. **さくら先生的精選文法教室**：整理本文的核心句型，提供清楚說明與自然例句。
5. **隨堂小測驗**：依本文與教學重點出題，遵循下方共通測驗規範。

每個單元至少要有一項直接連結本文的教學內容，不留空區塊或占位文字。詞彙與動詞區分工：精選單字以非動詞詞彙或慣用表現為主；動詞的主要解說集中在動詞教室，避免重複展開。其他單元（例如形容詞補充、文化小知識）依文章內容選擇加入，並放在上述五個必備單元之後。

## 詞條與例句朗讀、活用表與播放器（必備）

以 `N5/文章1/index.html` 為介面參考，依下列分工實作：

- **詞條發音**：精選單字與動詞教室的每張卡，在 `.vocab-header` 提供獨立的詞條朗讀按鈕，並以 `.vocab-romaji` 顯示羅馬字讀音；保留假名、繁中釋義，動詞另標類別。動詞預設朗讀ます形，標題並列辭書形時，須清楚標示按鈕朗讀的形式。
- **例句朗讀**：單字、動詞、助詞、文法教室的每個日文例句，另附單句朗讀按鈕與繁中翻譯。資料型教材可呼叫 `LessonRenderer.bindSpeechButtons()`，自動補齊 `.doc-lesson .example-box .example-jp` 的按鈕；例句按鈕不能取代詞條按鈕。
- **共用朗讀規格**：上述按鈕使用 `button.audio-btn`，附 `aria-label`，透過 `speakJapanese()` 或 `data-speak-text` 傳入指定詞條或例句的純日文。排除中文、羅馬字、按鈕圖示、括號中的重複形式及 ruby 附加讀音；一次點擊只觸發一次朗讀。
- **動詞活用表**：以 `button.conjugation-toggle` 呼叫 `toggleConjugation(id)`，控制帶唯一 ID 的 `.conjugation-table-wrapper`。若改用原生 `<details>`，須另外定義可見狀態，避免被全站 CSS 隱藏。
- **全篇播放器**：沿用 `.short-text-controls-row`／`.karaoke-controls` 結構和同級樣式。桌機控制列水平排列；手機將語速與播放控制上下排列，但播放與停止按鈕仍維持同列、不拉伸滿版、不重疊。

驗收須實際操作詞條與例句朗讀、展開活用表，並檢視桌機及手機版面，不能只確認 DOM 中有控制項。詳細檢查方式見 [lesson-validation.md](references/lesson-validation.md)。

## 隨堂小測驗

一般短文與階梯故事都必須提供隨堂小測驗，題目應對應文章內容或教學重點；階梯故事的題目應涵蓋各級版本的內容或句型。參考 `Progressive/Story01/index.html` 與共用 `js/quiz.js`，以選項按鈕逐題作答，選擇後立即顯示對錯、正確答案及該選項的中文解說，全部作答後顯示百分制總分。

沿用 `quiz-question-block`、`quiz-opt-btn`、`quiz-fb-*`、`quiz-score-summary` 與 `checkQuizQuestion` 的既有介面。確認題目 ID、答案索引與回饋相互對應；階梯故事另須確認切換級數後仍可作答。

## 教材品質原則

- 教學說明使用台灣繁體中文。日文原文、假名、例句與中文翻譯須互相對應。
- 依目標級數選擇詞彙與文法；不確定級數時標示為適讀程度，不宣稱官方分級結果。
- 逐句解析沿用該內容模式現有的 Ruby、羅馬字、翻譯和發音呈現方式；不要為了湊欄位而新增無教學價值的內容。
- 必備教學單元的內容以本文重點為準；例句應自然且能說明用法，不固定詞條、例句或測驗題數。
- 必備教學單元之外的詞彙補充、助詞延伸、形容詞與文化說明只在有教學價值時加入。
- 測驗答案要能由教材內容或教學說明支持，干擾選項應合理，回饋要清楚且友善。
- 精簡原文後重新核對：精選單字與教學引用須對應實際教材；原文若有助詞、活用或讀音問題，修正後保留核心句型與故事意思。不要把原始附加假名直接串進日文本文或 TTS。
- 使用圖片或其他來源素材時保留原始檔案與來源資訊。除非使用者明確要求，不要刪除或覆寫原始素材。

## 實作原則

1. 先檢查目標資料夾、同類單元與首頁入口，確認該模式目前使用的頁面和資料格式。
2. 優先沿用 js/ 下的共用音訊、朗讀、測驗、進度、UI 與 lesson-renderer 模組；避免複製播放器、測驗或進度邏輯。
3. 使用與目標頁面深度相符的相對路徑。一般 N 級單元位於 N5/文章N 等資料夾，回到主頁通常是 ../../index.html，樣式包含 ../../style.css 與本地 lesson.css。
4. 新增或更名單元時同步更新入口卡片、篩選標籤與唯一進度 ID。系列首頁與系列內單元要分別確認入口。
5. 保留既有單元的相容性；除非使用者要求，不要為了套用新模式而批次重寫舊頁。
6. 新增或修改互動教材時，先以 `pwsh -NoProfile -File scripts/check-site.ps1` 檢查結構，再在瀏覽器驗證本次涉及的操作與桌機／手機版面；結構或語法檢查通過不能當成功能正常的證據。驗收範圍與共用介面陷阱見 [lesson-validation.md](references/lesson-validation.md)。
7. 多篇來源依「多篇來源：逐篇獨立製作」逐篇完成製作與驗收；不得以先驗證一篇、再用程式批次套用其餘篇的方式交付。

Skill 規範的是內容與整合結果，不強制指定每個動畫、色碼或像素尺寸。視覺細節以共用樣式和目標系列的既有設計為準。
